4. Как работать пяти разработчикам
-----------------------------------

Нельзя всем напрямую отправлять изменения в main.

Каждый разработчик создаёт отдельную ветку:

git checkout main
git pull
git checkout -b feature/название-задачи

После изменений нужно проверить Python:

python -m py_compile app.py web_app.py

Затем сохранить и отправить ветку:

git add .
git commit -m "Описание изменения"
git push -u origin feature/название-задачи

После этого разработчик создаёт Pull Request в ветку main.

Изменения попадают в main только после проверки CI и одобрения другого разработчика.


5. Защита ветки main
---------------------

На GitHub откройте:

Settings -> Branches -> Add branch ruleset

Настройте:

- Branch name: main
- Require a pull request before merging
- Require approvals: минимум 1
- Require status checks to pass
- Block force pushes
- Block deletions

Это не позволит случайно сломать общую ветку.


6. Важное предупреждение о базе данных
---------------------------------------

Файл questionforge.sqlite3 публикуется вместе с проектом.

Он станет доступен всем, потому что репозиторий Public.
Не загружайте в приложение личные документы, секреты, пароли или персональные данные.

Файл .env публиковать нельзя.
OPENAI_API_KEY должен храниться только локально в файле .env.
